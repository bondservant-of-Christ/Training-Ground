# Barracks notes
- Classic scripts in src/ share global scope; load order is in index.html. State `S` persists to localStorage "barracks-v1"; migrations are S.v2/S.v3.
- Ranks: 10 ranks x 3 tiers, profLv() 0..29; zone t unlocks if floor(profLv()/3) >= t-1.
- calc(): atk=str*2+gear, def=end+gear, hp=50+vit*10+gear. Combat: dmgTo = max(1, round(raw - def*.5)); enemy hp=a*7, atk=h*.11+d*.5.
- Exercise types: "r" reps, "w" weight x reps (ranked vs bodyweight), "m" minutes (timed cardio; 1 row per workout, every 5 min counts as a set for rewards, max 6; counts toward Endurance). New exercises need a PAT entry in 07-exercise-info.js. Equipment "a" = anywhere, shown in every mode (Running, Walking). Renaming an exercise: add it to EXREN in 02-state.js so renameEx() carries best/pr/routines over (runs at startup and in adoptCloud).
- Rewards: XP 7*sets+25*rankups; gold 6*sets+25*rankups. Battle cooldown 300s, HP persists until healed.
- Enemy art: jagged full-body silhouettes (ENM in 10-enemies.js). No cartoon/realistic styles.
- HUD (#hud, built by drawHud() in 03-rank.js, refreshed on every save()): level + XP bar, streak, Steps, Gold. #info sheets open below it.
- Streak: S.streak/S.day, +1 per calendar day the app is opened (daily()). Steps: S.steps/S.wk, earned only from Cardio group exercises (100 per timed minute, 2 per rep), reset every Monday, spent on the Map to skip travel (walk minutes x 100).
- Run/walk travel is honor-system; no GPS verification. A trip finishes only when its timer runs out (Arrive) or by spending Steps to skip it; there is no manual minutes entry on the Map.
- Bump VERSION in sw.js each release. When a new service worker takes over, index.html reloads the page automatically (skipped mid-workout, mid-battle, or while building a routine).
- Map tab: mapView() shows a Map home (current location + section cards) unless msec=="combat", which shows the Combat Zone section (travel, zones, battles). go() resets msec.
- Accounts (src/12b-account.js): optional Firebase Auth (email/password + Google popup) and Firestore save sync, project training-grounds-933e5. SDK is lazy-loaded from jsdelivr (only on opening Account, or at startup if S.uid is set). Cloud doc saves/{uid} = {data: JSON of S, rev, updated}; rules in firestore.rules (paste into the Firebase console). S.uid/rv/mt/ms are sync bookkeeping. save() marks real progress; save(1) is a quiet save for housekeeping (streak tick, migrations) so it never wins a sync conflict. Newest real change wins; a device save that meets an account with different progress prompts the player to choose; a save linked to another account is never mixed in.
- Tests for sync were run with a mocked `window.firebase`; sign-in itself only works on the live site (authorised domain), not in the Artifact preview.
- Friends (src/12c-friends.js): signed-in only, mutual via friend requests. Firestore: players/{uid} = public card {name, code, lv, rk, un, av (96px jpeg), t}; stats/{uid} = friends-only {streak, day, best, gold, wk, eq, bio (max 160 chars, shown on the friend profile; untrusted, always esc()), t}; inbox/{to}/from/{from} = request {st: pending|accepted}; outbox/{uid}/to/{to} = sender's private index. firestore.rules lets only accepted friends read stats (paths use plain $(var) segments only, so the request lives under the receiver's inbox rather than a composite id). pubProfile() republishes card and stats after each successful sync when they changed. S.fc = own 6-char code. Decline, cancel and unfriend all delete the link (frRemove). A streak shows as 0 unless `day` is today or yesterday. Anything read from another player is untrusted: escape text, validate ids with okId(), pictures with safeAv(), gear ids against GEAR.
- Tests (not in repo) used a mocked `window.firebase` whose Firestore enforced the same access rules; the real rules have only been checked by publishing them in the console.
- Mend costs 10 MP + 5 per earlier cast in the same battle (mendCost(), B.mc); Fireball 12 MP + 5 per earlier cast (fireCost(), B.fc). Counters are separate and reset each battle; a spell is unusable once its cost passes max MP (20 + 2 per level). Balance target: Block + Mend must not be loopable; an ungeared new account is meant to lose zone 1.
- Sign out (acctOut) uploads unsaved progress first (flush()), then signs out and replaces the device save with a fresh one, so a signed-out device never holds a linked save. If the upload fails it warns and needs a second tap ("Sign out anyway"). A never-linked device save (Choose a save screen) is kept. Reset all data (rs) keeps the account link only while signed in (and then erases the online save too, as labelled); signed out it drops the link, so signing in again loads the online save instead of overwriting it.
- Box Knight (BK in 12c-friends.js): built-in joke friend on every signed-in player's leaderboard. Local only, not removable. Level 52, Sovereign I, 27,000 gold, all tier-9 gear, streak 132 on 2026-10-09 rising by 1 per day (bkStats()).
- Body (src/12d-body.js, Profile > Body): sex, age, height, activity, tape measurements and the weight log live ONLY in localStorage "barracks-body-v1:<uid or local>", never in S, so they are never synced, published or exported. Keep it that way. Only S.bw is shared (ranks need it); change it through setBw(). Body fat uses the U.S. Navy tape method, falling back to a BMI-based estimate without measurements; calories use Katch-McArdle with tape data, else Mifflin-St Jeor. Reset all data and "Erase my body details" wipe the current slot.
- Workout history: each S.log entry is {d, name, dur, ex, xp, g, st}; ex = [[exercise, [[weight or 0, reps or minutes], ...]], ...] for submitted sets only (entries from before 2026-10-10 have no ex; details are dropped past the newest 400). historySheet() lists them, workoutSheet(i) shows one; entry points are Barracks > Recent workouts and Training > Workout history. renameEx() also renames inside log entries.
- Mid-workout editing (05-training.js): rmEx(i) removes an exercise (second tap needed if it has submitted sets), exPick() opens the Add exercise picker (addEx). Both change only the running session `run`, never the saved routine. An exercise can appear once per workout.
